# Part 12A schema and security amendment proposal

## Decision

No new table or column is required for Phase 12. Existing domain tables and the authoritative
projections from Phases 7 through 11 contain the required source facts. The `notifications` table,
five-part deduplication key, recipient policies, unread index, `workloop_expiry_processing` login,
source-column grants, expiry insertion policy, and expiry audit policy support Part 12B without a
schema change.

One security amendment is required before Parts 12F and 12G can cut over sensitive downloads. The
current `append_audit_event` contract does not admit output-generation actions. Broadening that
generic function would make every runtime caller eligible for the new actions. The smaller option is
a separate fixed-purpose function named `public.append_phase12_output_audit`.

12A proposes the amendment but does not apply it.

## Revision placement

Part 12F creates the append-only revision immediately after the then-current Alembic head. The
revision has no table, column, index, enum, data backfill, or new login. Part 12G may extend the same
function's action allowlist in its own append-only revision if PDF and ZIP actions are not present in
12F. Do not edit an earlier revision.

## Function signature

```sql
public.append_phase12_output_audit(
  p_action text,
  p_entity_type text,
  p_entity_id uuid,
  p_format text,
  p_filter_digest text,
  p_source_digest text,
  p_renderer_version text,
  p_row_count integer,
  p_byte_count bigint,
  p_result text
) RETURNS uuid
```

The function is `SECURITY DEFINER`, owned by `workloop_migration`, has
`SET search_path = pg_catalog, public`, and qualifies every object. Apply `REVOKE ALL` from `PUBLIC`
and grant only `EXECUTE` to `workloop_runtime`. The function reads company, branch, actor, and request
context through the existing validated context readers. It accepts no actor, company, branch,
business date, free-text reason, filename, notification body, or output bytes.

## Exact allowlists

The function accepts these tuples and rejects every other value:

| Action | Entity type | Format |
| --- | --- | --- |
| `report_csv_exported` | `report` | `csv` |
| `attendance_csv_exported` | `attendance_period` | `csv` |
| `roster_csv_exported` | `roster_month` | `csv` |
| `leave_balance_csv_exported` | `leave_balance_year` | `csv` |
| `employee_csv_exported` | `employee_export` | `csv` |
| `nafis_csv_exported` | `nafis_report` | `csv` |
| `sif_previewed` | `payroll_run` | `sif_preview` |
| `sif_exported` | `payroll_run` | `sif` |
| `report_pdf_exported` | `report` | `pdf` |
| `payslip_pdf_exported` | `payslip` | `pdf` |
| `payslip_zip_exported` | `payroll_run` | `zip` |
| `letter_pdf_exported` | `letter_request` | `pdf` |
| `offboarding_letter_pdf_exported` | `offboarding_checklist` | `pdf` |
| `final_settlement_pdf_exported` | `final_settlement` | `pdf` |

`p_result` is `succeeded` or `denied_before_stream`. Success requires nonnegative counts and a
positive byte count except for preview, where byte count is the generated byte length and row count
is the preview record count. Digests use lowercase `sha256:` followed by 64 hexadecimal characters.
Renderer version is 1 to 64 ASCII letters, digits, dots, underscores, or hyphens.

## Inserted audit row

The function inserts one `audit_events` row with:

- context-derived `company_id`, nullable verified `branch_id`, actor kind, actor app-user ID, and
  initiated-by app-user ID;
- the allowlisted action and entity type;
- `p_entity_id` as the entity ID;
- `changed_fields` fixed to `['output']`;
- a fixed reason of `Phase 12 output delivery`;
- metadata keys `format`, `filterDigest`, `sourceDigest`, `rendererVersion`, `rowCount`, `byteCount`,
  and `result`; and
- the database timestamp supplied by `audit_events`.

Metadata accepts no extra key. The function returns the inserted audit UUID. A missing or invalid
context, inactive principal, unverified admin branch, invalid tuple, malformed digest, negative
count, or database error fails closed.

## RLS and grants

No direct `INSERT` grant on `audit_events` is added to `workloop_runtime`. Add one policy that permits
the function owner to insert only the exact row produced by the function, or reuse the existing
function-owned audit insertion mechanism if its predicate can enforce the same tuple. Do not add a
human `SELECT` policy for output audits. Existing authorized audit readers may read the new rows
under their current scope.

The output service receives no new `SELECT` grant on domain tables. It calls existing repositories
and source projections under `workloop_runtime`. The amendment does not grant file storage, network,
large-object, filesystem, or notification access.

## Verification requirements

The revision verifier must prove:

- exact predecessor and one Alembic head;
- owner, invoker behavior, pinned search path, and revoked `PUBLIC` execution;
- successful insert for every allowlisted tuple under matching company and branch context;
- denial for unknown action, entity type, format, result, malformed digest, negative count, null
  principal, inactive principal, stale branch, cross-company entity, forged actor, and direct table
  insert;
- safe metadata with no bytes, rows, names, bank data, SIF content, letter text, or filename; and
- downgrade removes only the new function, policy, and grant while preserving all audit rows already
  written.

## Rollback

Disable Phase 12 output routes before revoking function execution. Preserve existing audit rows.
Then revoke `EXECUTE` from `workloop_runtime`, drop the Phase 12 output audit policy if one was added,
and drop `append_phase12_output_audit`. Do not drop `audit_events`, change prior audit rows, widen the
generic audit writer, or alter the expiry login.
